# PALATE

**A private archive of taste.** 메뉴와 그날의 식사 경험을 모으는 개인용 아카이브입니다. 별점이나 공개 리뷰 없이 **호 / 보통 / 불호**와 **다시 먹을 의사**를 따로 기록합니다.

React · TypeScript · Vite. 데이터는 **localStorage + JSON**으로 관리합니다. 개인 기록 관리에 데이터베이스, Supabase, 계정 서버나 분석 추적 도구가 필요하지 않습니다. 외부 음식점 검색·메뉴 조회의 연결 범위는 아래를 참고하세요.

## 실행

Node.js 22.12 이상이 필요합니다.

```sh
npm ci
npm run dev
```

```sh
npm test          # 데이터 의미, 연결 관계, 백업 검증
npm run build    # TypeScript 검사 + 정적 빌드 + 오프라인 셸
npx playwright install chromium
npm run test:e2e # CRUD, 사진, 모바일, 백업, 저장 실패, 오프라인
```

`npm run preview`로 `dist/` 빌드를 확인할 수 있습니다. GitHub Pages용 상대 경로와 hash routing을 사용하므로 하위 경로 `/food/`에서도 새로고침할 수 있습니다.

## 구현된 경험

- 빠른 기록: 메뉴 검색/직접 등록 → 호불호 → 재주문 의사 → 저장
- 같은 메뉴의 여러 식사 기록, 기록 수정·삭제, 브랜드·장소·메뉴 등록과 정보 수정
- Collection의 격자·목록, 기간·평가·재주문·브랜드·분류·태그·첫 식사 필터
- 메뉴 상세의 전체 기록, 최근 기록, 날짜별 사진·메모
- Journal, 장소와 브랜드별 탐색, 전체 검색, 기록에서 계산하는 취향 통계
- 사진 6장까지, 브라우저에서 긴 변 1,600px 이하 WebP 압축
- 사진을 포함하는 JSON 백업·검사·교체 복원, CSV 내보내기, 개별 사진 다운로드
- 저장 실패 시 기존 데이터 보존, 손상된 데이터의 복구 화면, 다른 탭 변경 반영
- PWA 아이콘과 설치 메타데이터, 릴리스별 셸 캐시, 첫 방문 후 오프라인 기록

처음에는 빈 아카이브로 시작합니다. **예시 아카이브 둘러보기**를 선택하면 가상의 기록과 예시 사진을 불러옵니다. 사진은 실제 식당·메뉴를 촬영한 것으로 간주하지 마세요. 예시 모드는 계속 표시되며, 설정에서 예시를 지우고 시작할 수 있습니다.

## 고르기와 릴스 보관함

첫 화면과 기존 디자인은 유지하고 **Choose / 고르기** 탭을 추가했습니다. 저장한 음식점과 프랜차이즈에서 메뉴를 보며, 먹고 싶은 마음과 실제 호불호·횟수를 함께 확인합니다. 음식점과 메뉴 각각 관심을 표시할 수 있고 새 식사 기록을 남기면 그 메뉴의 관심만 자동 해제됩니다.

프랜차이즈 7개 브랜드·57개 대표 메뉴를 버전이 있는 로컬 JSON으로 제공합니다. 아직 먹지 않은 메뉴가 Collection을 채우지 않으며, 기존 메뉴를 다시 가져와도 기록·관심·ID를 보존합니다.

릴스와 음식점 링크는 먼저 보관하고 나중에 이름·메모를 붙이거나 여러 음식점·메뉴에 연결합니다. 아이폰 단축어 수신 주소와 설정 안내를 앱 안에 포함했습니다.

- [전체 사용 흐름과 데이터 보존](docs/DISCOVERY.md)
- [아이폰 공유 단축어 설정](docs/IPHONE_SHORTCUT.md)
- [외부 음식점·메뉴 조회 서비스 연결](docs/RESTAURANT_SERVICE.md)

기본 음식점 이름 검색은 Photon의 OpenStreetMap 기반 공개 검색이며 결과 범위가 네이버·배민과 같지는 않습니다. **개별 음식점 메뉴 자동 조회는 선택적 조회 서버를 배포·연결해야 합니다.** 서버 코드와 테스트는 포함되어 있지만 연결되지 않은 상태에서 메뉴를 제공하는 것처럼 표시하지 않습니다. 모든 음식점의 전체 메뉴를 보장하지 않으며 기존 수동 추가도 사용할 수 있습니다.

## 데이터 소유권

저장 키는 `palate.archive.v1`입니다. 한 브라우저 프로필의 로컬 사용자 1명을 지원합니다. 모든 엔티티에는 `user_id`가 있으며 JSON 복원 시 소유자와 참조 무결성을 검사합니다. 이 구분은 서버 인증이나 암호화 기능이 아닙니다.

같은 브라우저 프로필을 쓰는 사람은 아카이브를 열 수 있습니다. 다른 기기와 자동 동기화하지 않으며 브라우저 데이터 삭제·시크릿 모드 종료 시 데이터가 사라질 수 있습니다. 설정의 **JSON 백업**을 정기적으로 사용하세요. 사진도 JSON 안의 data URL로 함께 내보냅니다. localStorage의 용량은 브라우저마다 다르며 사진이 많으면 제한에 도달할 수 있습니다. 저장에 실패하면 폼을 유지하고 기존 저장값을 덮어쓰지 않습니다.

복원은 병합이 아닌 **전체 교체**입니다. 20MB 이하의 PALATE v1·v2 백업을 검사한 뒤 기록 수와 교체 확인을 표시합니다. 브라우저 저장 한도를 넘는 파일은 복원하지 않으며 원본은 유지합니다. CSV는 열람용이며 복원에는 JSON이 필요합니다. 사용자가 올린 사진과 식사 메모는 서버로 전송하지 않습니다. 외부 음식점 검색과 조회에는 검색어·조회할 URL만 해당 공급자에게 전달합니다.

기존 v1 저장값과 JSON을 계속 읽으며 첫 변경을 저장할 때 v2로 확장합니다. 관심 표시와 보관함·연결 정보도 JSON 백업에 포함됩니다.

## GitHub Pages

저장소 **Settings → Pages → Source: GitHub Actions**를 선택합니다. `main`에 푸시하면 데이터 테스트와 빌드를 통과한 정적 파일을 Pages로 배포합니다. PR과 `main`의 CI는 브라우저 테스트도 실행합니다. 서비스워커는 배포된 빌드에서만 등록합니다. PWA 설치에는 HTTPS 또는 localhost가 필요합니다.

배포 주소가 바뀌면 브라우저 저장 공간도 달라집니다. 주소를 옮기기 전에 기존 주소에서 JSON을 백업한 뒤 새 주소에서 복원하세요. 앱 셸은 정적 호스팅으로 제공되며 개인 식사 기록은 각 사용자의 브라우저에만 남습니다.

## 보드 타일

[Life Board](https://github.com/KINGJNU-sakayume/board)에 보여 줄 **보드용 목록**(규격 v1)만 Life Hub에 올립니다. 식사 기록·메모·사진 자체는 올리지 않습니다. 승인되어 이 앱에 저장된 식사와 위시만 쓰고, Life Hub 수신함의 대기 후보는 쓰지 않습니다. 사진은 브라우저 안의 `data:` 이미지라 보드에 띄울 수 없어 표지는 글자 칸(`{mono}`)입니다. 날짜는 `11/7`처럼 날짜로 적습니다("어제" 같은 말은 쓰지 않음).

| id | 이름 | 형태 | 크기 (처음) | 처음부터 보임 | 데이터 출처 |
|---|---|---|---|---|---|
| `recent` | 최근 먹은 것 | strip(정사각) | 2x1, 4x1 (2x1) | ✓ | 최근 식사 8개(메뉴당 하나), 메뉴 이름 |
| `last` | 마지막 식사 | 한 줄 | 2x1, 4x1 (2x1) |  | 가장 최근 식사: 메뉴 · 장소, 호/보통/불호, 날짜와 한 줄 메모 |
| `again` | 다시 먹을 것 | 목록 | 2x1, 2x2 (2x2) |  | 마지막 식사에서 '다시 먹는다'를 고른 메뉴와 날짜 |
| `wish` | 먹고 싶은 것 | 목록 | 2x1, 2x2 (2x2) |  | 위시(메뉴·음식점·브랜드)와 담은 날짜, 없으면 빈 상태 안내 |

식사 기록이 하나도 없으면 `recent`·`last`·`again`은 빠지고, 기록도 위시도 없으면 아무것도 올리지 않습니다. 목록을 만드는 순수 함수는 `src/lib/board-tiles.ts`의 `buildBoardTiles(archive, now)`, 지어낸 값의 예시 출력은 [`board/sample.json`](board/sample.json)입니다.

**올리는 때.** `PUT /palate/v1/board`(스코프 `food:board`). 타일에 영향을 주는 변화가 생기면 마지막 업로드에서 10분이 지났으면 바로, 아니면 10분이 차는 때 한 번 보냅니다(10분에 한 번 이하). 닫혀서 못 보낸 변경은 다음에 앱을 열 때 바로 보냅니다. 내용(`generated_at` 제외 sha256)이 마지막 성공과 같으면 보내지 않지만, 앱을 열 때 마지막 성공이 하루보다 오래됐으면 같아도 한 번 보냅니다(보드의 '오래됨' 표시 방지). Life Hub에 연결돼 있지 않거나, 예시 아카이브이거나, 기록이 없으면 올리지 않습니다. 업로드 실패는 앱의 다른 기능에 영향을 주지 않으며, `400`/`413`은 같은 내용으로 다시 보내지 않고 개발자 콘솔에만 남깁니다.

**어느 기기에서.** Life Hub는 앱마다 최신 목록 하나만 보관하고 이 앱의 기록은 기기 안에만 있어서, 두 기기가 올리면 서로 덮습니다. 그래서 설정 > Life Hub의 **「이 기기에서 보드에 올리기」**(기기별, **기본 꺼짐**)를 켠 기기만 올립니다.

**다시 연결이 필요한 경우.** 보드 업로드에는 `food:board` 권한이 필요합니다. 이 권한이 생기기 전에 만든 연결은 첫 업로드가 `403 insufficient_scope`로 오며, 이때 연결(토큰)은 **끊지 않고** 설정에 "보드에 올리려면 Life Hub에 다시 연결해 주세요"만 표시합니다. 「다시 연결」을 한 번 하면 됩니다. 수신함·동기화는 그대로 동작합니다.

# 데이터 모델

`src/types/model.ts`가 실제 스키마이며 루트 `Archive.schema_version`은 2입니다. v1 백업과 기존 저장 키를 유지하며 읽을 때 호환 변환합니다.

| 엔티티 | 역할 |
| --- | --- |
| User | 로컬 프로필, 이름과 생성 날짜 |
| Brand | 메뉴와 지점을 묶는 선택적 상위 분류 |
| Place | 실제 식사 장소, 브랜드 없이도 생성 가능 |
| Menu | 음식 이름과 종류, 선호도는 별도로 저장하지 않음 |
| MenuOffering | 메뉴와 장소의 다대다 연결, 통화·가격 |
| EatingRecord | 메뉴를 먹은 사건, 날짜·평가·재주문·메모·가격 |
| Photo | 식사 기록에 연결한 WebP data URL과 치수·순서 |
| Tag / RecordTag | 사용자 태그와 식사 기록의 다대다 연결 |

모든 개인 엔티티와 연결에는 `user_id`를 둡니다. 이름은 NFKC 정규화, 소문자화, 공백·문장부호 제거로 비교합니다. 이름과 브랜드가 같은 메뉴는 기존 메뉴를 사용하며 별도 생성도 명시적으로 선택할 수 있습니다. 같은 메뉴를 서로 다른 지점에서 먹어도 메뉴는 하나입니다.

기록 삭제는 해당 사진과 태그 연결을 삭제하고 메뉴는 보존합니다. 장소 삭제는 Offering을 삭제하고 관련 기록의 장소를 비우며 기록·사진·메뉴는 보존합니다. 사용하지 않는 태그는 백업 호환성을 위해 남습니다.

복원 시 버전, 필드 형식, enum, 날짜, 유한한 양수 치수·금액, 고유 ID, 소유자 일치, 모든 외래 참조, 이미지 data URL 형식을 검사합니다. HTML과 SVG 업로드는 사용하지 않습니다. 잘못된 백업은 적용하지 않습니다. 모든 저장은 JSON 직렬화 후 단일 localStorage 키에 원자적으로 반영합니다.

Wish는 BRAND / PLACE / MENU 대상의 독립적인 관심 표시입니다. SavedLink는 릴스·음식점 URL, 메모와 여러 대상 연결을 저장합니다. 모든 새 데이터에 user_id를 포함하고 복원 시 소유자·대상 참조·중복·https URL을 검사합니다.

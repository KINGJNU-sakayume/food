# 먹기 전에 고르기

첫 화면은 기존 Collection입니다. 새 **Choose / 고르기** 탭 안에서 내 음식점, 프랜차이즈, 릴스 보관함을 오갑니다. 디자인의 종이색·활자·얇은 구분선은 유지합니다.

## 메뉴와 관심

음식점·브랜드의 ‘가보고 싶다’와 메뉴의 ‘먹고 싶다’는 별도로 저장합니다. 아직 먹지 않은 메뉴를 보통이나 불호로 취급하지 않습니다. 실제 식사 기록에서 계산한 호·보통·불호와 횟수를 관심 표시 옆에서 확인합니다.

새 식사 기록을 저장하면 **그 메뉴의 관심 표시만** 해제됩니다. 맛의 평가와 재주문 의사는 별개이며, 음식점의 관심 표시는 유지됩니다. 예전 기록을 수정하거나 삭제할 때는 새로 표시한 관심을 해제하거나 복구하지 않습니다.

프랜차이즈는 `src/data/franchises.json`의 버전이 있는 수록 목록을 사용합니다. 현재 7개 브랜드, 57개 대표 메뉴이며 실시간 전체 메뉴·판매 여부·가격을 보장하는 피드가 아닙니다. 출처와 수록 날짜를 화면에 표시합니다. 브랜드를 선택하면 해당 메뉴를 가져오며 이미 먹은 같은 브랜드·이름의 메뉴는 기존 ID를 사용합니다. 다시 불러와도 기록과 관심 표시는 보존합니다.

불러온 메뉴는 먹기 전에는 Collection에 표시하지 않습니다. 먹으면 Collection에 편입되고, 마지막 식사 기록을 나중에 지워도 메뉴는 보존합니다. 개별 식당에서 이름이 같은 메뉴는 장소별로 구분합니다.

## 음식점 검색과 외부 메뉴

이름 검색은 사용자가 검색 버튼을 눌렀을 때만 Photon의 OpenStreetMap 기반 공개 검색을 호출합니다. 한국 영역의 음식점·카페·베이커리 등 결과를 사용하고 결과에 없는 음식점을 만들어내지 않습니다. 검색 간격은 최소 1.2초이며 같은 검색은 메모리에 30분간 캐시합니다. 입력 자동완성이나 지역 전체 수집을 하지 않습니다. 검색어는 Photon에 전달되지만 개인 평가·사진·링크 보관함은 전송하지 않습니다.

공개 검색의 데이터 범위는 네이버지도나 배민과 같지 않습니다. Photon 운영자는 합리적인 소규모 사용을 허용하며 가용성을 보장하지 않습니다. 사용량이 늘어나면 조회 서비스 설정을 통해 자체 호스팅이나 다른 공급자로 바꿔야 합니다. [Photon 사용 안내](https://github.com/komoot/photon#demo-server), [OpenStreetMap 출처·라이선스](https://www.openstreetmap.org/copyright).

네이버 이름 검색과 공개 페이지의 메뉴 자동 조회를 위한 선택적 서비스는 [RESTAURANT_SERVICE.md](RESTAURANT_SERVICE.md)에 설명합니다. 이 서비스가 배포·연결되지 않은 상태에서도 프랜차이즈 수록 메뉴와 기본 이름 검색, 링크 저장을 사용할 수 있습니다. **서비스를 연결했다고 모든 음식점의 메뉴가 자동 제공되는 것은 아닙니다.** 메뉴가 제공되지 않거나 읽기에 실패하면 그 사실을 표시하고 기존 데이터는 유지합니다.

## 보관함

릴스는 제목이나 음식점 지정 없이 URL만 먼저 저장할 수 있습니다. 나중에 제목·짧은 메모를 붙이고 음식점·브랜드·메뉴 여러 개에 연결합니다. 네이버지도·배민 등 음식점 링크도 보관하며 ‘음식점으로 정리’에서 정보를 가져오거나 이름과 출처를 저장할 수 있습니다. 연결한 음식점 화면에서 관련 릴스를 다시 열 수 있습니다.

보관함은 링크·메모를 보관하며 인스타그램 영상 자체를 다운로드하거나 자동으로 내용을 분석하지 않습니다. Instagram 공유 추적 파라미터는 제거하고 같은 정규화된 링크는 한 번만 저장합니다. 링크를 삭제해도 연결한 메뉴·식사 기록은 삭제하지 않습니다.

## 기존 데이터와 백업

데이터는 v2 스키마로 확장하며 기존 저장 키 `palate.archive.v1`은 유지합니다. v1 데이터를 읽을 때 원본을 덮어쓰지 않고 메모리에서 관심·보관함을 추가합니다. 다음 저장부터 v2로 기록합니다. 이전 JSON 백업을 계속 불러올 수 있고 새 백업에는 음식점·관심·보관한 링크·다중 연결이 함께 포함됩니다.

공유 수신 주소는 `#/receive?text=<URL 인코딩한 공유 텍스트>`입니다. hash 안에 공유 내용을 넣어 정적 호스팅 요청 경로와 분리합니다. URL을 검사한 후 현재 저장 데이터를 읽어 추가하므로 이미 있는 아카이브를 새 빈 아카이브로 교체하지 않습니다. 같은 링크는 중복 저장하지 않으며 잘못된 링크는 저장하지 않습니다.

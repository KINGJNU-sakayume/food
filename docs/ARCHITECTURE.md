# 기술 구조

React 18 + TypeScript + Vite 정적 SPA입니다. 상대 경로 빌드와 hash routing으로 GitHub Pages 서브디렉터리를 지원합니다. 개인 데이터를 저장하는 서버는 없습니다. 음식점 검색은 조회 공급자 인터페이스로 분리하며, 선택적 읽기 전용 Worker의 주소를 설정할 수 있습니다. 비밀 값은 클라이언트에 포함하지 않습니다.

`src/lib/data.ts`는 브라우저 UI와 분리한 순수 데이터 함수, 파생 선호도, 백업 검사와 저장 진입점입니다. App의 commit은 현재 참조를 바탕으로 새 아카이브를 생성하고 검사한 뒤, 저장 성공 후에만 화면 상태를 교체합니다. 저장 용량 오류는 폼과 기존 값을 보존합니다. 손상된 저장값은 자동 초기화하지 않고 원본 내려받기와 명시적 복원을 제공합니다.

다른 탭의 변경은 storage 이벤트로 반영하고 열린 편집 폼을 닫아 오래된 값으로 덮어쓰는 상황을 줄입니다. 단일 브라우저 프로필과 단일 탭 편집이 기본이며 localStorage는 동시성 트랜잭션이나 다중 기기 동기화를 제공하지 않습니다.

사진은 createImageBitmap으로 읽고 방향을 반영해 캔버스로 축소, WebP 0.8 품질로 저장합니다. JSON은 사진을 포함해 완전한 이동 단위가 됩니다. 브라우저 용량 한계 때문에 대규모 사진 라이브러리는 향후 별도 저장 방식이 필요합니다.

빌드 후 해시된 자산 목록으로 서비스워커를 생성합니다. 설치가 완료된 셸은 오프라인에서 실행되며 기록도 로컬에 저장합니다. 새 릴리스는 기존 창을 모두 닫고 다시 열면 활성화됩니다. 배경 동기화나 서버 백업은 없습니다.

Node 테스트는 반복 기록·삭제 무결성·소유자와 참조 검증을 검사합니다. Playwright는 실제 저장소·모바일·사진 처리·복원·용량 실패·오프라인을 확인합니다. CI는 브라우저 테스트를 포함하고 Pages 배포 전에는 데이터 테스트와 프로덕션 빌드를 실행합니다.

고르기와 보관함은 Wish·SavedLink를 추가한 v2 아카이브를 사용합니다. 기존 키와 v1 JSON은 읽기 호환되며 첫 저장에서 확장합니다. 프랜차이즈 목록은 버전이 있는 JSON이고, 외부 조회 실패는 저장된 메뉴를 삭제하지 않습니다. 자세한 연결 범위는 [RESTAURANT_SERVICE.md](RESTAURANT_SERVICE.md)를 참고하세요.

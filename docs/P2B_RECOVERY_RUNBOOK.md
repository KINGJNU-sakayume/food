# PALATE P2-B 운영 전 복구·안전 검증 안내

## 상태와 전제
- P2-A: IndexedDB 복제 및 SHA-256 원본 동등성 검증 (Draft PR #5)
- P2-B: IndexedDB를 기본 저장소로 사용, **명시적 활성화** (Draft PR #6, #5를 선행 필요)
- `palate.archive.v1`: 전환 이전의 **동결된 localStorage 원본**, 절대 자동 삭제/덮어쓰기하지 않는다.
- `palate.storage.primary.v1`: 활성 저장소의 위치를 나타내는 작은 키. 최초 DB는 `on`, 복구 DB는 `db:palate-storage-recovered-<UUID>` 형태다.
- 기존 DB `palate-storage-primary-v1` 및 이후 복구용 DB는 명시적인 사용자 작업 전에는 지우지 않는다.
- **IndexedDB는 기기 내 저장 공간이다.** iPhone 브라우저 삭제, 홈 화면 앱 삭제, 저장공간 정리, 브라우저 정책으로 모두 사라질 수 있다. 백업 파일을 파일 앱/클라우드/외부 저장소에 보관해야 한다.

## 전환 (기기별로 개별 수행)
1. 기존 앱의 설정에서 JSON 전체 백업을 내려받아 파일 앱 등 사이트 외부에 보관한다. 파일을 다시 읽고 기록/사진 수가 정확한지 확인한다.
2. 동작 중인 다른 탭·홈 화면 PWA를 닫는다.
3. P2-A의 IndexedDB 사본 만들기 및 무결성 검사를 완료한다.
4. P2-B의 체크박스에 동의한 뒤 전환한다. 원본과 검증 사본의 SHA-256 및 JSON이 다르면 전환하지 않는다.
5. 새로고침 후 전체 기록·사진 수와 JSON 내보내기를 검사한다. 새 식사 하나를 기록한 뒤 재접속해 유지되는지 확인한다.
6. 기존 localStorage는 **전환 시점의 복구 자료**이며 이후 식사를 포함하지 않는다. 추가 기록을 남길 때마다 외부 JSON 백업을 갱신해야 한다.

## 오류 발생 시 (절대 원본을 지우지 말 것)
- 복구 모달에서 현재 로컬 원본 텍스트를 먼저 별도로 내려받는다.
- **레거시 원본만 변경됐고 IndexedDB가 유효한 경우:** '검증된 최신 IndexedDB 기록 내보내기'를 누르면 원본 충돌 검사만 건너뛰고, 사진/관계 무결성 검사를 통과하는 최신 JSON을 내려받는다. 자동 병합하지 않는다.
- **IndexedDB 자체가 손상된 경우:** 검증된 백업을 자동으로 만들 수 없다고 표시한다. 데이터베이스를 임의로 삭제하지 않는다. 이전에 직접 저장한 JSON 파일을 선택한다.
- **외부 백업 복원:** 선택한 JSON을 검증한 후, 별도의 IndexedDB를 새로 만들고 모든 사진·데이터를 재검증한다. 이후 활성 저장소 위치만 바꾼다. 기존 DB와 오래된 localStorage는 보존한다.
- **자동 복구 금지:** 오래된 localStorage를 최신 IndexedDB보다 우선하도록 조용히 되돌리지 않는다. 기존 키가 손상됐다는 이유로 빈 아카이브를 덮어쓰지 않는다.
- 파일 선택 후 복구 체크박스는 다시 선택해야 한다. 복구가 성공했는지 재접속 및 백업 내보내기로 재확인한다.
- 기존 DB가 손상되어 검증된 JSON을 추출할 수 없는 경우에는 원래 DB를 그대로 유지하고 외부 백업/수동 복구가 필요하다. 이 기능은 **모든 종류의 손상을 자동으로 복구한다는 보장이 없다.**

## iPhone Safari · 홈 화면 PWA 실기기 QA (아직 미완료)
- Safari 웹에서 JSON 백업을 실제 파일 앱에 보관한 후 파일이 정상인지 확인
- iPhone 사진 선택, 6장 첨부, 수정·삭제, 여러 식사의 사진 갤러리
- P2-A 사본 생성, P2-B 전환 후 백그라운드 앱 종료·재실행, 저전력 모드
- Safari 탭과 홈 화면 PWA의 저장공간 공유 여부 **가정하지 말고** 각각 별도 데이터와 기록을 확인
- 새로고침, 오프라인, 앱 재실행, 기기 재시동 후 기록 유지
- 서로 다른 탭의 편집 충돌, 동기화 알림, 기록 연타 중복 방지
- 외부 JSON 내보내기/복원 및 복원 후 최신 기록 존재 여부
- 저장용량이 부족한 상황에서 원본/이전 DB가 보존되는지 확인
- **통과 전까지 사용자 운영 데이터로 저장소 전환을 권장하지 않음**

## 중요한 제한과 후속 P2-C
- 화면에서는 이미지 데이터 URL을 아직 재구성하므로 메모리 사용량을 줄이는 최적화 작업이 남아 있다.
- 단말 간 동기화 기능은 아직 없다. Life Hub가 쓰려면 인증된 원격 Inbox와 outbox/revision 설계가 필요하다.
- 장소 삭제 시 과거 식사의 장소 연결을 비우는 기존 동작은 별도 보존 정책으로 변경할 계획이다.
- 테스트 성공과 실제 iPhone Safari 검증은 다르다.
